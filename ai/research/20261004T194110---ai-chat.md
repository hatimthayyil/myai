Background: `20261004T172045---shitty-optchat.md`, `20261004T171431---optchat-cache-claude-code.md`. Supersedes the nap/cover/sync parts of `20261003T091838---memory-git-ref.md` and `20261004T152738---memory-user-level.md`.

## Decisions (user, 2026-10-04)

1. One store: the chat log is `ai memory` (`refs/ai/memory` in the bare repo `~/.ai/memory`, `AI_MEMORY_DIR`). Messages have a kind: user, talk, tool, echo, note. `ai memory note` appends a `note`, from any session.
2. Pure binary tree (§3): a level-0 node per message, merges of two children, free nodes, `NODE` = 512 bytes. The view is the incremental fold (§5): append, merge the most due built pair, never split, refold at load; `VIEW` = 128,000 bytes. `id+n` addressing and zoom per §3/§7.1. Raw-16 blocks and the alpha-bisection cover are gone.
3. Variable-size messages: one blob each (below). One commit per mutation.
4. Single machine. Sync, merge, fingerprints, renumbering, origins and the remote are gone; ids are permanent positions. Multi-writer safety stays: CAS on the ref. Multi-machine sync is a backlog item.
5. Compaction: never by agents. The compactor (§4.1 pump, JOBS 8, RETRY 10 s forever, first failure reported once; §4.2–4.3 context block, SCALE, size retries in one conversation, TRIES 5, shortest kept; COMPACT verbatim with agent name "MyAI") runs inside `ai chat` and as `ai memory nap`. One compactor per memory: advisory lock `compact.lock` in the memory dir; a second one exits at once. `ai memory note` spawns a detached `ai memory nap` when a node is due (output to `nap.log`; `AI_MEMORY_NAP=0` disables); `note` prints no prompts.
6. Model access through a pluggable `Backend` (open a conversation with a system prompt; say a message, get text, same context for retries). Only implementation: Claude Code, `claude -p --model sonnet --effort medium`, stream-json in/out, `--verbose --include-partial-messages --no-session-persistence --setting-sources "" --strict-mcp-config --system-prompt-file F --tools "" --safe-mode`, env `CLAUDE_CODE_PROMPT_CACHE_TTL=5m`, `DISABLE_PROMPT_CACHING=1`. Other APIs later.
7. `ai memory` keeps `init`, `wake` (print the view), `note`, `nap`, `zoom`, `show`, `grep`, `config`, `import` (OptMem bootstrap → `note`). `forget` and `sync` are gone.

## Storage layout

Under `refs/ai/memory`, one commit per mutation:

```
log/<i>>8 as %04x>/<i&255 as %02x>        message i: "ts kind repo head branch agent model session\n" + text
tree/<l>/<s>>8 as %04x>/<s&255 as %02x>   nodes 256s..256s+255 of level l, one line each:
                                           "ts model text" (text flattened), empty = not built
```

- `ts` UTC `YYYYMMDDThhmmssZ`. Header fields: whitespace → `_`, empty → `-`. Free nodes have model `-`.
- Every commit also writes the free nodes it completes (a short message's leaf, a parent whose children fit 512 bytes together), so free nodes never wait for a compactor.
- The view is not stored: `Mem::load` reads every level and refolds.
- Next to the repo: `compact.lock` (compactor lock), `nap.log` (background naps' output).

## Deviations from the spec

- Node text stored flattened; a free merge is `a + " " + b` (spec: `"\n"`), same size, identical everywhere it is shown.
- No process lock for the log (§2 "one writer"): many sessions append notes; CAS serializes commits, and ids are assigned inside the CAS. Only the compactor is exclusive.
- Durability: git objects + ref update, no explicit fsync (§2 asks one per line). Open.
- Dates are UTC; `date(id)` (stage 2) renders local time.
- `wake` prints the view for sessions outside the chat, paged for harness output caps, later parts pinned to the first part's commit.

## Stages

1. Done: store, tree, view fold, zoom, compactor library with the `claude -p` backend, `ai memory nap`, note-triggered background nap. Tested with fake backends (and a fake `claude` script end to end).
2. `ai chat`: turn loop on `claude -p` (fresh process per turn, killed at its first `result`, mid-run messages via stdin + replay), priming for the cross-turn view cache, zoom/date over a stdio MCP subcommand, REPL, `dontAsk` permission mode with a tool allowlist, system prompt = MASTER + VIEW_DOC + AGENTS.md. The compactor runs in the chat process (`Compactor::log`, `settle` before each turn).

## Stage 2 decisions (user, 2026-10-04)

- System prompt = MASTER + VIEW_DOC + the user's global instructions + the AGENTS.md of the repo `ai chat` starts in (none outside a repo). Read once at start, byte-identical for the whole chat; edits take effect on restart.
- `zoom id+1` is capped and paged, like `grep`.
- Child hygiene: `claude` children die with the chat (PR_SET_PDEATHSIG); dropping the compactor kills its running calls.
- No fsync: git objects + ref update suffice on one machine.
- `nap.log` is kept whole: a few lines per run.
- Compactor lock race fixed: after any note commit the memory ends compacted with no further trigger.
- Compaction cost on the subscription: measure in the first week of use.
- COMPACT and VIEW_DOC describe `note` as "notes recorded by other agent sessions" (spec: "memories from before this chat"): notes arrive from parallel sessions during the chat.
