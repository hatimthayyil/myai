# cli.rs

- `Runtime`: how commands reach the compactor's model. Default: Claude Code (`ClaudeCode::compactor`), spec options, `nap_on_note` unless `AI_MEMORY_NAP=0`. Tests pass a fake backend and turn the trigger off; the binary tests set `AI_MEMORY_NAP=0` in the sandbox (one test turns it on with a fake `claude` script on `PATH`).
- `wake`: prints the view (`Mem::load` over the latest snapshot, budget `VIEW`), `<chat>` … `</chat>`, paged by `PART_CHARS`/`PART_LINES` (harness output caps). Multi-part reads are pinned to the commit printed in "Not awake yet. Run: ai memory wake <k> <commit>", so a note landing between parts cannot shift a line. Never refuses: unbuilt lines show the placeholder.
- `note`: one line, ≤ `ENTRY_CHARS` bytes (default and cap `NOTE_MAX` = `NODE - "note: "` = 506), so a note is always its own (free) leaf. The setup block prints the configured limit. After saving, if a node is due, spawns a detached `ai memory nap` (own process group, stdin null, output appended to `<memory>/nap.log`) and returns. Prints no nap prompt.
- `nap`: runs the compactor until nothing is due on the latest snapshot. Only one compactor per memory (`compact.lock`, see compact.rs): a nap that cannot take the lock exits at once ("exit", not "wait", so note-spawned naps never pile up). Each round ends by releasing the lock (`drop(c)`), then re-checking `pending` on the latest snapshot and try-locking again if anything is due. No note is ever left unbuilt: a note's commit happens before its nap's try-lock; if that try-lock fails, the holder releases later, so its re-check sees the commit and either builds it or loses the lock to a nap that took it after the commit and loads a snapshot containing it. `Runtime::before_release` is the test seam for this interleaving (`a_note_whose_nap_finds_the_lock_taken_still_gets_built`). A fresh backend per round: dropping a compactor stops its backend for good (`Live::kill_all` closes it), so a second round must not reuse it. Created only when something is due. Failures: printed once per node, retried every `RETRY` forever (spec §4.1); Ctrl-C stops.
- `zoom`/`show`/`grep --before` take `id+n` (a bare `id` is `id+1`); `line_id` validates against `T`. `zoom` output and the "No line id+n." refusal follow spec §7.1.
- `zoom id+n [part]`: long output is paged by PART_CHARS, with a continuation command; part numbering starts at 1.
- `import`: `YYYY-MM-DD <text>` lines → `note` messages at UTC midnight, any length; dates must not go back.
- `Cli::exec` / `broken_pipe`: a closed stdout is not an error.
