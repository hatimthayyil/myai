# store.rs

Spec: `ai/research/20261004T194110---ai-chat.md` (storage layout). Bare repo per user (`~/.ai/memory`, `AI_MEMORY_DIR`), all data under `REF`.

- Layout: message `i` is its own blob at `log/{i>>8:04x}/{i&255:02x}` (header line `ts kind origin repo head branch agent model session`, then the text verbatim). Nodes of level `l` live in line segments `tree/<l>/{s>>8:04x}/{s&255:02x}`, segment `s` = nodes `[256s, 256s+256)`, one line per node (`ts origin agent model session text`, text flattened), empty line = not built. Messages are variable size (echoes up to 30k, pastes larger), so each gets its own blob: a tail segment of big messages would be rewritten on every append. Nodes are small and read all at once at load (refold), so they are segmented; levels are sparse (free nodes and parallel merges land out of order), hence empty lines rather than a dense prefix.
- `log_len`: the last entry's number + 1, from two tree reads. Ids are positions and permanent: single machine, append-only.
- `mutate`: one commit per mutation, CAS on the ref; a lost race redoes from the new head. Multi-writer safe (notes from many sessions, one compactor).
- `Edit`: one mutation's new messages and nodes over a snapshot. Every node write cascades: the parent is built in the same commit when both children exist and `a + " " + b` fits `NODE` (free node). `push` builds the free leaf (`kind: text` ≤ `NODE`). So after any commit every free node whose sources exist is built, and no compactor needs a free-node pass.
- `put_node`: first write wins (a built node never changes); refuses a node beyond the log.
- Free nodes record agent, model and session `-`; every node records the store's origin.
- Origin: `ai.memory.origin` in the repo's git config, 6 Crockford base-32 characters from `getrandom`. `find` reads it and creates it under the config lock when absent, so `init` (`create` → `open`) makes it. `append` stamps it on messages without one; `set_origin` replaces it (one word, no whitespace: it is a header field). Public so a rebuild can append old messages with their own `ts`, origin and provenance, then set the store's origin.
- `commit_id`: `wake`'s pin is a full commit hex; no prefix lookup (would need gix's revision feature).
- `pretty`, `AtPath`: paths as the user types them; `<path>: <strerror>.` errors.
- `Store::open` refuses a missing/non-repo dir (only `init` creates); committer falls back to `ai memory <ai@localhost>`.
- Time order: the log is in `ts` order, an invariant `Edit::push` keeps. An unstamped message (`Message::new`) gets `max(now, last ts)` when it is pushed, and the push re-runs on every `mutate` retry, so a writer that loses the CAS restamps on the new head. Before, `Message::new` stamped the time at creation: of 16 parallel `note`s, one could stamp at second k, lose the race to one stamped at k+1, and land after it (the flaky `parallel_processes_lose_nothing`). Stamping inside the mutation is not enough alone: a stamp taken after reading a head whose last message was stamped by a clock that later stepped back would still go backwards, hence the `max`. A message given a `ts` (import, a rebuild) keeps it but must not precede the last message: the store refuses it ("cannot follow ... the log is in time order") rather than move it, since a moved date would be a false record. The lock-free CAS stays: serialising appends with a file lock would also fix it, but CAS + restamp needs no lock file, no stale-lock handling and keeps notes from blocking on a nap's commit. The order lets a line's date range be read from its first and last messages only (meta.rs).
