# tui/mod.rs

Threads: the session thread renders by sending `Show`s down a channel (`Tui` is the `Render`); one UI thread owns the terminal and the `App`; one reader thread forwards crossterm events.

Hangup (2026-10-06 bug: orphaned chats spun at 90% CPU for hours after their terminal closed, ignoring SIGTERM): crossterm 0.29's event source (`source/unix/mio.rs`, `try_read`) loops forever when reading the tty fails with anything but `WouldBlock`/`Interrupted`, as a hung-up tty does (EIO), so `event::poll`/`read` never return. The reader then never ended, and the UI thread joined it, so even after SIGHUP the session's exit waited forever; SIGTERM went to a session that had already returned. Now: the reader `poll(2)`s stdin itself (100 ms) and calls crossterm only with a zero timeout right after stdin shows no `POLLHUP`/`POLLERR`/`POLLNVAL`; a hangup or any crossterm error sends `Msg::Hangup`, which ends the UI with a `BrokenPipe` error (quiet exit) and an `Exit` to the session. Each frame checks the tty first too (a resize asks crossterm for the cursor). Nothing joins the reader, and `Tui::stop` waits at most 2 s for the UI thread, so a stuck terminal can never keep the process alive. Tested on a real pty (root `tests/cli.rs`): a closed master ends the chat within 2 s; SIGTERM ends it idle, during priming and during a turn, restoring the terminal. Keys become session `Event`s on the session's own channel, so the session knows nothing about terminals. The UI thread batches every message waiting, then draws one frame inside a synchronized update (DEC 2026); it ticks every 250 ms while a turn runs (spinner, elapsed) and every second otherwise (priming age).

Setup: raw mode, bracketed paste, and the kitty keyboard protocol's disambiguate flag when supported (Shift-Enter distinct from Enter). `restore` undoes all of it once (guarded by `ACTIVE`) and runs from: normal finish, any UI thread error, `Drop` of `Tui` (session error or panic unwinding), and a panic hook installed once that runs before the default hook. SIGTERM/SIGHUP still reach the session as `Exit`; the session returns and `Tui::finish` flushes what is left and restores. A failing UI thread sends `Exit` to the session; a session sending to a dead UI gets an error.

Not alt-screen: an inline viewport (see term.rs), so the chat lives in the terminal's own scrollback. Ctrl-Z is not handled (raw mode disables ISIG; no suspend).
